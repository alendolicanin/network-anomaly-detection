# Provenance and feature schemas

`provenance.json` records two sets of fingerprints:

- `recorded_experiment` identifies the code, configuration and decision used in the reference execution.
- `distribution` identifies the supplied modules, configuration and metadata after naming cleanup.

Training settings, selection rules and numerical results are unchanged. The descriptive version label was removed from configuration and metadata, and paths were renamed. These edits change file hashes without representing new training. `normalized_metadata` maps each affected record to its original and distributed SHA-256 values.

Hashes embedded in the saved decision and result summaries continue to identify the original execution artifacts. `results/decision.sha256.json` verifies the distributed decision file. `scripts/check_saved_results.py` checks both sets of identities, while `RELEASE_MANIFEST.json` covers the complete distribution.

`data/` contains prepared-data identities, source verification records and manifest summaries. The summaries omit absolute dynamic-library paths (`environment.threadpools[].filepath`) and the descriptive version label. Each original manifest hash is retained separately; its summary is not a byte-identical copy. Library versions, hardware, partitions and schemas are retained.

Matrix and metadata checksums refer to the full experiment archive. Those large artifacts are not included and must be generated by preparing the source data. `schema/` records input features and constants. Use a fresh experiment directory with the supplied code; existing full experiment archives retain their recorded identities.
